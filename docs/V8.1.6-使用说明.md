# 美丽武器 V8.1.6

本版以 V8.1.5 正式完整包为基线，只修复第一条礼物被挡在入队之前的问题，并修改指定的按钮颜色和文字。保留已成功工作的后续礼物监听、账号绑定、主页资料读取、Emoji、模板素材、随机制片、合成进度、停止任务、手动合成/播放、直播输出和更新功能。

## 更新后使用

1. 在旧版“设置 → 检查更新”下载并安装 V8.1.6。更新保留旧版，新版建立在独立版本目录。
2. 在新版设置中打开网页助手文件夹，在 Edge 禁用旧助手、加载“美丽武器V8.1.6_抖音网页助手”，刷新直播平台。此次修复在扩展内容脚本中，必须完成助手换版；软件安装不能代替浏览器扩展确认。
3. 打开并保持“礼物明细”，确认页面连接并开启“自动监听”后送礼。Edge 保持打开，可被直播伴侣遮挡；建议将 anchor.douyin.com 加入始终活动网站。只保留一张直播平台标签页。
4. 礼物入队 → 绑定唯一账号 → 读取并核对头像昵称 → 随机模板合成 → 绿色“立即播放”。仍由本人点击播放，不自动播放。

## 首条修复

失败日志的首条记录已经读到了昵称和礼物，但没有被证明是新增记录，因此未进入资料读取或合成。原规则要求空列表容器提前存在并稳定 1.2 秒；容器晚创建或首条较快到来时，这个条件可能不成立。

本版提前观察已经打开的空礼物区域，记录首条元素的实际插入，并允许该条昵称稍后渲染完成。不会简单把“找到一条记录”当作新礼物。初次打开已有的历史记录、加载中的历史、滚动、整批替换、无可靠空区域依据仍不猜测；不放宽账号、头像或昵称核验。附加捕获诊断记录首条插入依据，便于现场核查。

后续底部新增和有记录编号的礼物判定保持原样。相同礼物无稳定记录编号时，既有“不保证零漏单”提示保留，不能把提示等同于任务一定失败。

## 界面

直播模式“打开直播输出窗口”采用普通模式同名按钮的实际背景色、文字色、边框色和同一点击处理，只打开输出窗口。左侧素材导入按钮改为“导入视频”“导入图片”，导入功能未改变。

## 保留与测试

V8.1.5 完整包全部条目逐项校验并保留；源码去除版本号差异后，仅 gift-dom.js 和 layout.js 有修改。旧程序、素材、模板、配置、任务和成片未删除。每次启动建立新场次、当前面板归零和历史任务恢复继续采用 V8.1.5 实现。

独立 Edge 中测试四种首条复现、空区域及历史/加载/滚动防护、真实助手任务绑定、同用户重复礼物、不同用户、真实 FFmpeg 合成、手动播放、任务临时页关闭和原有连续礼物回归。测试使用隔离端口、数据目录和受控网页，错误用户视频及误关非任务标签页为零；未代替真实直播验收，不宣称零漏单或所有网页结构均已覆盖。

GUI 已重建；原 Go 核心和后台、实际 FFmpeg 二进制继续保留。所有完整包 ZIP 条目 SHA256 已验证。原 V8.1.5 资料及运行基线保存在资料和 components/versions 中，源码位于 components/runtime/v816_source。个人日志、直播任务、个人模板媒体不上传公共仓库。
