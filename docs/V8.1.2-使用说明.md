# 美丽武器 V8.1.2 使用说明

本版修复主页昵称里的图片表情被漏读，导致头像关联失败的问题；同样修复礼物昵称的图片表情读取。增加主页头像区域校验和重复节点去重、浏览器标签页暂时拒绝操作时的限时重试，并在重启时清空当前用户和手动昵称，拒绝助手回推上次读取。保留 V8.1 的排版、头像图标、设置、模板、素材、随机制片、持久队列、原手动读取/合成/播放和内置/NDM 更新功能。

## 必须完成的一次助手更新

1. 结束当前播放/合成，在旧版“设置 → 检查更新”选择内置下载器，等待新目录安装和自动切换。旧目录保留，不需要删除文件。更新源仍是 https://raw.githubusercontent.com/1196197579-a11y/BeautyWeapon/main/latest.json 。
2. 新版“设置 → 打开新版网页助手文件夹”。在 Edge 的 edge://extensions/ 开启开发人员模式，禁用旧美丽武器助手，加载此文件夹“美丽武器V8.1.2_抖音网页助手”。不要同时启用两套助手，不需要删除旧助手文件夹。
3. 刷新已经打开的 https://anchor.douyin.com/ 平台页面。仅重新加载扩展而不刷新旧页面，不能替换已注入页面的旧代码。
4. 展开礼物明细，在程序中开启自动监听。看到“礼物明细已连接”后，再送出新的测试礼物。开启前已显示的记录仅作为基线，不会补做。

本次程序更新不会代替浏览器确认扩展更新。仍使用旧助手时，程序会暂停监听并提示更新助手；原手动主页读取继续兼容旧助手。

## 正常直播流程

先检查至少一个未归档的完整模板可以正常合成。保持 Edge 礼物明细展开、只开一张监听平台页，并将平台与用户主页加入 Edge 始终活动的网站，避免睡眠/丢弃。

新送礼 → 独立任务 → 获取并验证账号/头像/完整昵称 → 随机有效模板 → 合成 → 待播放。普通模式点击“播放下一条”，或在直播模式核对头像和昵称后点击“立即播放”。不会自动播放下一条；“打开直播输出窗口”只打开窗口。

## 本次修复及边界

抖音可能将昵称中的表情显示为 IMG 节点。现在依据该昵称内的表情 alt 还原完整昵称，同时用于礼物行、点击前校验、主页昵称和头像说明，避免同一用户在不同阶段被读成不同昵称。

头像从当前公开账号的昵称/头像区域取得；导航栏、其他账号链接、推荐区域均排除。同一个图像的重复节点不算多个用户；多个不同头像、账号不匹配、旧昵称仍然拒绝。账号标识、主页 canonical、任务临时页标记的校验继续保留。

浏览器报告 Tabs cannot be edited right now 时最多重试 8 秒，创建前查任务标记避免重复，更新/关闭前每次重新核验归属。永久错误仍会明确报告；不会无限打开或误关用户标签页。

重启程序后当前头像、昵称、锁定和手动昵称清空，助手缓存的上次读取不重新用于合成；打开/刷新用户主页或点击助手重新读取后正常接收。模板、素材和已就绪的队列仍保留，待播缩略图显示的是该视频的用户，不是启动后新捕获的人。

此次已只读核对实际小号公开主页的图片表情结构及昵称/头像一致性。实际送礼全过程、窗口覆盖和长时间运行仍需现场复测；没有独立记录编号的重复内容/虚拟列表复用仍有漏单风险，不宣称零漏单。无法追踪的原生 async/await 打开仍保持人工核对。

## 旧任务和异常按钮

同机模板、素材、更新/NDM 设置和 automation-v8 任务存档保持原位置。此前失败任务继续保留；已经具有 sourceUrl/账号标识的头像失败任务可在加载新版助手后直接重试；刷新后旧礼物行的节点标记可能失效，不能凭昵称自动补做。应从原送礼记录核对用户主页，用“核对身份”填写完整地址后重试；不再需要的失败任务可“归档异常”，不删除文件。

“重试”重跑身份验证；“重新选模板”针对素材/模板失败；“开始新场次”须先关闭监听、处理完任务并等待助手缓冲清空。归档异常不表示任务已合成或已播放。

换电脑请先导出、导入“模板＋素材”；完整 ZIP 不包含私人素材或抖音登录资料。回滚时退出新版，在旧入口传入 --skip-active；不要删除 active.json 或任务目录。原 Go 核心、后台及 FFmpeg 位于 components，仍是必要组件。

源码和重建脚本：components/runtime/v812_source。新 EXE 已实际重建；旧 Go 二进制原样保留。没有删除用户文件。
