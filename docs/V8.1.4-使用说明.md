# 美丽武器 V8.1.4

本版修复已由实际失败日志确认的阻断点：正确主页已加载昵称和头像时，缺少 canonical/og:url 不再强制失败。程序仍核对原送礼记录的唯一账号、每次读取独立的任务标记、稳定昵称和唯一关联头像；公开账号信息有冲突、头像不唯一、资料仍在加载、任务标记不对或昵称明显不一致时继续停止制片。

## 更新和一次复验

1. 旧程序“设置 → 检查更新”，使用内置下载器或已配置的 NDM 更新到 V8.1.4；新目录安装，旧版保留。
2. 新版“设置 → 打开新版网页助手文件夹”。在 Edge 扩展中禁用旧助手，加载“美丽武器V8.1.4_抖音网页助手”，刷新直播服务平台。只更新软件不会替换浏览器已经加载的助手代码。
3. 开启自动监听。对已保存正确主页地址的失败任务点“重试”，无需再送礼；该任务重新读取和合成。没有可靠主页地址的任务仍需从原礼物记录核对账号，不能凭相同昵称猜测。
4. 成片进入待播队列后，核对头像和昵称，点“播放下一条”或直播模式“立即播放”。不会自动播放。

## Emoji

礼物昵称、点击目标和用户主页使用同一个 Unicode 表情读取规则：文字表情和图片 alt 中的表情都保留。头像图片的说明文字不会混入昵称；昵称里的表情图片缺少可靠文字时明确报错，不把表情删掉后猜测身份。

账号识别使用主页账号标识，昵称仅作为资料一致性检查。比较时只统一 Unicode NFC 和可选的文字/彩色显示选择符，实际昵称保留原文字；不删除肤色、连接符、国旗或组合成员，不把不同表情当成同一个昵称。

长昵称按完整字符簇截到原有 7 字符展示上限，再加省略号；完整昵称仍保留用于身份检查和队列展示。预览和制片使用随包携带的 Noto Color Emoji 字体，运行时不需要联网下载字体。Emoji 画风可能与系统默认字体略有差别。

字体来自 Google 官方 Noto Emoji 项目 https://github.com/googlefonts/noto-emoji，按 SIL Open Font License 1.1 随软件分发，原字体未修改。固定提交、字体 SHA256 和完整授权位于 components/runtime/emoji。后续 Unicode 新表情或平台改变 HTML 结构仍可能需要适配，本版不声称支持所有未来表情和网页改版。

## 旧数据和失败日志

重启清空当前手动读取的头像、昵称和手动输入；历史任务、已收数量和捕获警告属于持久场次记录，保留供重试和核对，不表示重启后又读取了一遍。旧异常不会自动变成就绪，需要点“重试”重新验证。

失败会继续写入桌面“美丽武器_读取失败日志”，包括在建立身份读取租约之前发生的目标点击失败。日志只包含有限公开页面事实，不记录登录凭证、网页全文或图像内容。归档异常与开始新场次不删除文件；本版不清空用户历史记录。

## 实际自测与边界

按用户提供日志的 DOM 事实重现“无 canonical、无标题、含表情昵称、两个无关登录者头像”，新版读取通过。独立 Edge 中完成多用户/重复送礼、静默任务页、身份错误拦截、随机模板、真实 FFmpeg、待播队列、手动输出、Service Worker 恢复和临时页关闭自测。

还读取实际公开抖音主页，获取完整表情昵称和真实头像，合成真实视频并关闭任务页；送礼事件为受控测试，未冒充真实直播送礼验收。11 类表情均验证文字/图片读取、完整字符截短、生产 PNG 图层与真实视频编解码像素。受控测试中错误用户视频和误关原有页面数为零；虚拟化列表存在无法可靠捕获的情形，不能承诺零漏单。

启动 EXE 已重建。原 Go 核心和原 FFmpeg 二进制保持基线，未从原 Go 源码重建；新源码位于 components/runtime/v814_source。所有旧版本、模板、素材、设置和日志均保留，不删除用户文件。
